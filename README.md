# 折页阅读顺序校样 Web 应用

在行列纸格上标注正反面页码，逐步添加“沿某条网格线向左 / 右 / 上 / 下折叠”的步骤，
系统模拟面片翻转、上下层级与页码朝向，支持任意一步回放，并在全部折叠完成后输出
**从封面到封底的页码阅读顺序**。

当出现下列两种印张折手中的典型错误时，系统会**拒绝执行该步并在画布上标出冲突纸格**：

- **折线不在当前外轮廓上（contour）**：移动纸瓣镜像后越过纸块边缘形成悬空；
- **两侧厚度不一致（thickness）**：折线两边叠层厚度不等（包折 / 不等厚折法）。

技术栈：Node.js + Express（服务端），原生 HTML / CSS / Canvas（前端），
折叠模拟为一份零依赖的纯逻辑引擎，浏览器与服务端共用同一份代码。

---

## 一条命令启动

```bash
docker compose up --build -d
```

启动后在浏览器打开：

> **http://localhost:3000**

停止：

```bash
docker compose down
```

> 不使用容器时（本机已装 Node.js ≥ 18）也可以：
> `npm install && npm start`，然后访问同一地址。

方案 JSON 保存在容器内 `/app/data`（Compose 已声明命名卷 `fold-data`，删除容器不丢方案）。

## 使用说明

1. **创建行列纸格**：左侧输入行数、列数（1–12），点击“创建网格”。
2. **标注页码**：点击画布中的任一纸格，在弹层中分别填写该片叶子的
   **正面页码** 与 **反面页码**（留空表示空白页）。
3. **添加折叠步骤**：
   - 在左侧选择竖直线（左右折）或水平线（上下折）及位置，再点四个折叠按钮；
   - 或者直接点击画布边缘的折叠手柄（▲▼◀▶）。
   - 方向含义：**“向左折”= 折线右侧的纸瓣向左翻过折线并落下**，其余同理。
   - 非法手柄显示为红色虚线；点击非法折法时不会执行，并在下方给出原因、
     在画布上用红底标出冲突纸格。
4. **逐步回放**：用顶部的 ⏮ / ◀ / ▶播放 / ▶| 按钮或进度条，查看任一步后的
   面片位置、叠层厚度（`×N`）、朝上的是正面还是反面、以及页码是否倒置（`⟲倒`）。
5. **阅读顺序**：右侧“最终阅读顺序”按骑马钉式折帖叶序输出
   封面 → … → 封底的页码序列；倒置页码以红底标出，空白页显示“空白”。
   尚未收成单叠时，会分组列出每个分离叠层的序列。
6. **自动拼版**：仅当**全部折叠步骤都可合法回放且已收成单叠**时，
   右侧“自动拼版”卡片才允许输入**起始页码**与**成品页数**：
   - 系统按最终封面→封底的阅读槽位依次写入连续页码，再反向映射到
     每个原始纸格的正/反面；
   - 成品页数小于纸格总面数（`行数×列数×2`）时，序列末尾的剩余槽位
     留空白，预览表中逐行标明空白槽位所属的原始纸格与面；
   - “生成预览”**不会改动当前标注**；确认后才批量写入；若现有标注非空，
     确认前会汇总所有将被覆盖/清空的位置（写入前还会二次确认）；
   - 非法折叠、未收成单叠或页数超出容量时，生成按钮禁用并给出具体原因。
7. **折手自动寻路**：右侧“折手自动寻路”卡片中，指定某个**原始纸格**及其
   **正面 / 反面**作为最终朝上的封面：
   - 系统从当前方案**已合法回放的末态**出发，枚举现有引擎允许的全部折线与
     落向（即画布上手柄对应的所有 180° 折叠，先经同一套 contour / thickness
     校验），用 BFS 搜索把纸收成符合目标单叠的**最短**后续步骤；
   - 仅支持 **不超过 4×4** 的网格，搜索上限为**最多 8 个后续步骤、2 秒**：
     枚举完仍无解时提示“**无解**”，达到任一步数/时间上限仍未确认方案时
     提示“**搜索超限**”，二者分别显示；
   - 结果最多展示 **3 条等长最短方案**，逐条列出逐步折法
     （追加后的步骤序号、折线位置与落向），并标明最终落点格位与封面
     正立 / 倒置；封面相同但内页顺序或朝向不同的方案不会被互相合并；
   - 点击任一方案的“追加并回放”，即把该方案步骤**追加到当前步骤末尾**并
     进入既有回放（直接定位到最后一步），随后仍可逐帧回放、编辑或保存；
   - 若当前末态已经是目标单叠，返回 0 步方案并直接提示，无需追加。
8. **保存 / 载入**：
   - “保存到服务器”将方案 JSON 存入容器数据卷，可通过“已存方案…”再次载入；
   - “导出 JSON / 导入 JSON”在本地文件与应用之间交换方案。

### 方案 JSON 格式

```json
{
  "name": "8页折帖",
  "rows": 2,
  "cols": 2,
  "labels": {
    "0,0": { "front": "4", "back": "5" }
  },
  "steps": [
    { "axis": "v", "line": 1, "dir": "r" },
    { "axis": "h", "line": 1, "dir": "d" }
  ]
}
```

- `labels` 的键为 `列,行`（0 基），值为该格正反面页码字符串；
- 步骤中 `axis`：`v` 竖直线 / `h` 水平线；
- `line=k` 表示第 `k-1` 与第 `k` 列（或行）之间的网格线（`1 ≤ k < 列/行数`）；
- `dir` 为纸瓣落向：竖线用 `l` / `r`，横线用 `u` / `d`。

## 折叠模型

- 每个面片持有 3 个单位方向向量（右 `x`、下 `y`、正面法线 `n`）；
  竖直 180° 翻折令 `x, n` 反向，水平翻折令 `y, n` 反向，由此得到：
  - 每片叶子朝上的是正面还是反面（`n` 的 z 分量）；
  - 页码正立还是倒置 180°（`y` 的 y 分量）。
- 移动叠翻面后内部倒序，再整体压到静止叠之上，得到真实的上下层级。
- 校验规则：
  - **外轮廓**：每个移动格镜像后的落点必须已被占用（压到静止瓣或与瓣内另一格配对），
    否则该格及其悬空落点被标为冲突；
  - **厚度**：移动格压到静止格位时双方层数必须相等，否则两侧格位都被标为冲突。

### 折手自动寻路模型

- 搜索起点是“当前方案全部步骤合法回放”后的末态；现有步骤非法（回放冲突）时
  不允许寻路，须先修正。
- 每一步只枚举该网格内现有的全部竖/横折线 × 两个落向，并复用引擎同一套
  外轮廓 / 厚度校验；非法折法不会进入搜索树。
- BFS 按层展开，故首批命中目标的方案即为**最短**且彼此等长，最多保留 3 条。
- 去重状态键包含三个维度，缺一不可：
  - **各格叠层顺序**（每个格位上自上而下面片的排列）；
  - **面片朝向**（每个面片 3×3 朝向标架的 9 个分量，区分正反面与正/倒置）；
  - **相对位置**（叠层所占据的格位）。
  因此“封面是同一格同一面、但内页顺序或倒置情况不同”的结果不会被误合并。
- 目标判定：全部面片收成单个叠层，且顶片面片为指定原始纸格、其指定面
  （正面法线朝上为正面、否则反面）朝观察者。
- 资源边界：仅 `rows ≤ 4 且 cols ≤ 4`；搜索深度最多 8 步、墙钟最多 2 秒。
  状态空间枚举完毕仍无命中为“无解”；中途到达任一边界为“搜索超限”。

## 运行测试

```bash
npm test
```

服务端另有 `POST /api/simulate`（body 同方案 JSON，可用 `upto` 指定回放步数）返回
叠层、面片朝向与阅读顺序，便于脚本化校验折手方案。

`POST /api/impose` 在方案 JSON 之外附加 `startPage`、`pageCount`，返回自动拼版结果：
`labels`（写回每个原始纸格正/反面的连续页码，两面皆空者省略）、
`slots`（逐槽位的页码、空白标记、`origin` 原始纸格、`face` 面别、`upright` 朝向）、
`capacity`、`blankTrailing` 以及 `overwrites`（将被覆盖的现有非空标注）。
前置条件不满足时返回 `ok:false` 与具体错误码
（`contour` / `thickness` / `not_single_stack` / `too_many_pages` / `bad_start` / `bad_count`）。
自动生成的标签就是普通 `labels`，保存、导入导出与 `/api/simulate` 回放均原样保留。

`POST /api/fold-path` 在方案 JSON 之外附加
`target: { cell:"x,y", face:"front"|"back" }`，从方案**已合法回放的末态**
出发做折手自动寻路（可选收紧 `maxSteps` / `timeLimitMs`，服务端一律夹紧到
8 步 / 2 秒）。成功返回：

- `status`：`solved`（找到最短方案）/ `already`（末态已是目标单叠，0 步）/
  `no_solution`（枚举完仍无解）/ `limit`（达到 8 步或 2 秒上限，搜索超限）；
- `length`：最短后续步数（无解/超限时为 `null`）；
- `schemes`：**至多 3 条等长最短方案**，每条含
  `steps`（逐步 `{axis,line,dir}`，可直接追加到方案 `steps` 后回放）、
  `cover`（`cell` 原始纸格、`face` 朝上的面、`upright` 正立与否）、
  `finalCell`（单叠落点格位）；
- `visited` / `expanded` / `elapsedMs`：搜索统计，`truncated` 表示方案数超过 3 条被截断
  （此时 `goalCount` 为该深度上命中的方案总数）。

前置条件不满足时返回 `ok:false`，错误码为
`grid_too_large`（网格超过 4×4）/ `bad_grid` / `bad_target`（目标纸格越界或
面别非法）/ `replay_conflict`（当前方案存在非法折叠，附 `stepIndex`、`conflicts`）
/ `bad_limit`。搜索去重使用完整状态键（各格叠层顺序 + 面片朝向标架 + 相对位置），
不会把封面相同但折后结果不同的状态误合并。
